# Runtime sprites

These PNGs and `catalog.json` are generated by `uv run sprites bundle` using
[`image-generation/game-sprites.json`](../../image-generation/game-sprites.json).
`src/sprites/generated.ts` contains literal Metro `require()` calls. No model,
Python runtime or source video is needed in the app.

The package has 44 atlases / 312 poses: the barbarian player, five Wetlands
enemies and five Hollow Delve enemies, each with idle, walk, attack and death.
Source hashes and the additional bundle frame stride are in `provenance.json`.

All eleven entities use 128×128 frames. Player and Wetlands actions have eight
authored poses; Hollow Delve actions have six. The Wetlands roster uses detailed imagegen references and sheets
in [wetlands-128-v1](../../image-generation/enemy-sprites/sequences/wetlands-128-v1/README.md).
Its [portable animated review](../../image-generation/enemy-sprites/sequences/wetlands-128-v1/review.html)
includes the unchanged player for comparison.
The [Hollow Delve roster](../../image-generation/enemy-sprites/sequences/hollow-delve-v1/README.md)
contains troglodytes, cave spiders, bone slimes, beardless dwarves and gnolls.
The [v2 revisions](../../image-generation/enemy-sprites/sequences/hollow-delve-v2/README.md)
replace the troglodyte with a hunched, tailed creature and give the dwarf red
eyes and an axe, with boot-based contacts during the downward chop.

For a choppier package, keeping every second **exported** pose:

```bash
uv run sprites bundle --frame-step 2
```

Omitted poses become longer holds, so duration stays unchanged. One-shots keep
their final pose even when the stride misses it. `uv run sprites bundle`
restores the recipe's defaults. Repacking replaces the named generated sheets
and registry; it does not delete source generations or unrelated files.
The current player and Wetlands set each have eight designed poses, so the
default keeps every pose. Set `frame_step` per entity in the recipe to
choose different cadences. Rebuilding requires those local source exports;
running the app only requires this package.

For a fresh local Wan generation from the selected pixel reference, use a new
run directory on a machine with the installed CUDA models:

```bash
uv run sprites all --definition content/players/PLAYER.toml \
  --reference image-generation/player-sprites/references/barbarian-club-profile-v1/pixel-reference.json \
  --run image-generation/sprite-pipeline/runs/barbarian-local-v2 \
  --actions idle walk attack death --size 128 --frame-step 2
```

Then point the player's manifest in `game-sprites.json` at that run's
`exports/barbarian_player/manifest.json` and bundle again. The currently selected
player uses the imagegen source sheets described in its
[sequence recipe](../../image-generation/player-sprites/sequences/barbarian-club-v1/README.md).

Add another exported entity manifest to the recipe, run the bundle command,
and use its stable ID in content or `<EntitySprite entityId="..." action="..." />`.
Named actions are supported. An unavailable action falls back to idle,
reference, or the first available state. An unknown entity uses the existing
code sprite. No renderer edits are needed when adding a biome's art.

`EntitySprite` is positioned at a ground point. It uses each entity's facing,
pivot, reference height and height scale; facing is mirrored only when needed.
Skia samples the selected atlas rectangle with nearest filtering. Frame holds,
pausing, speed changes, repeated action events and one-shot endings are handled
by the shared playback code. Attacks return to idle; deaths remain down.

`npm run test:sprites` renders the production `SpriteTile` through the real
Skia CPU backend. It compares every atlas tile pixel-for-pixel with its source,
then checks exact 2× nearest scaling and mirrored output for the first, middle
and last poses of every action. It is also included in `npm test`.
Reports and rendered strips go to `/tmp/frpg-sprite-render-audit`; strip columns
show idle, walk, mid-attack and settled death. This checks actual drawing code
without a device, alongside the UI tests for playback and game integration.

Preview all entities with the exact game atlases:

```bash
uv run python -m http.server 8765 --bind 127.0.0.1
# Open http://localhost:8765/image-generation/game-sprites.html
```

The current Wetlands set has residual shading, body-volume and gait variation,
documented in its [review notes](../../image-generation/enemy-sprites/sequences/wetlands-128-v1/README.md).
The earlier 64px experiment and its review remain in `runs/wetlands-selected`.
Existing design/motion cleanup is tracked by `frpg-umv` / `frpg-kfl`.

The first expedition now uses the curated Wetlands enemies and their draft
stats: Toad, Corpse, Strider, Hag, then Hulk. This is a runtime expedition order;
the content catalog's random-spawn membership remains unchanged. Hollow Delve
is chapter four, unlocked by clearing Frostbound Keep, with Troglodyte, Spider,
Slime, Dwarf and Gnoll encounters and its own scenery. Embercrypt and Frostbound
Keep retain their fallback art. Existing pre-snapshot saves retain their old roster;
new runs snapshot the dungeon so later content changes cannot swap their enemies.
To intentionally refresh the compact roster from canonical content:

```bash
uv run python scripts/runtime_roster.py --biome wetlands --output src/game/rosters/wetlands.json
uv run python scripts/runtime_roster.py --biome hollow_delve --output src/game/rosters/hollow_delve.json
```
